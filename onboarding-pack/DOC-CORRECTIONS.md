## Finding 1 — Wrong start command (`node app.js`)

**README claim** (`sample-app/README.md` line 10):
```
node app.js
```

**Reality:**  
There is no `app.js` at the repo root or inside `sample-app/`.  
The real entry point is [`src/index.js`](../sample-app/src/index.js:1), and
[`package.json`](../sample-app/package.json:5) declares:
```json
"main": "src/index.js",
"scripts": { "start": "node src/index.js", ... }
```

**Correct command:** `npm start` **or** `node src/index.js`

## Finding 2 — Wrong default port (3000 vs 8080)

**README claim** (`sample-app/README.md` line 14):
> The API will be available on **http://localhost:3000**.

**Reality:**  
[`src/config.js`](../sample-app/src/config.js:18) line 18:
```js
port: parseInt(process.env.PORT, 10) || 8080,
```
When `PORT` is not set the server binds to **8080**, not 3000.
[`sample-app/.env.example`](../sample-app/.env.example:7) also ships `PORT=8080`.

## Finding 3 — Wrong database technology (MongoDB vs Postgres)

**README claim** (`sample-app/README.md` line 20):
> `DATABASE_URL` – connection string for the **MongoDB** database.

**Reality:**  
[`src/config.js`](../sample-app/src/config.js:21) comments on line 21:
```
// Expected to be a Postgres URL, e.g. postgres://user:pass@localhost:5432/taskflow
```
[`src/db.js`](../sample-app/src/db.js:13) line 13 explicitly validates:
```js
if (!config.databaseUrl.startsWith('postgres://')) {
  console.warn(`[db] DATABASE_URL does not look like a Postgres URL...`);
}
```
The service is Postgres-only. A MongoDB URL would trigger a warning on every start.

## Finding 4 — Wrong auth module (legacy-auth is dead code)

**README claim** (`sample-app/README.md` lines 24–25):
> Authentication is handled by the **legacy-auth** module, which checks an
> API key on each request.

**Reality:**  
[`src/auth/legacy-auth.js`](../sample-app/src/auth/legacy-auth.js:1) line 4–6:
```
// This was the original auth approach based on API keys. It has been
// replaced by session.js and is no longer imported anywhere in the app.
```
[`src/index.js`](../sample-app/src/index.js:10) line 10 imports and uses
`requireSession` from `session.js` — not `legacy-auth.js`:
```js
const { requireSession } = require('./auth/session');
...
app.use('/tasks', requireSession, taskRoutes);
```
Auth now requires a **Bearer token** (`Authorization: Bearer session-<JWT_SECRET>`),
not an `x-api-key` header.

## Finding 6 — `JWT_SECRET` env var not documented (missing, required)

**README claim:** The Configuration section documents only `DATABASE_URL`.

**Reality:**  
[`src/config.js`](../sample-app/src/config.js:25) line 25:
```js
jwtSecret: required('JWT_SECRET'),
```
`required()` throws at startup if the variable is absent. The app cannot start
without it. It is also used directly by [`src/auth/session.js`](../sample-app/src/auth/session.js:13)
line 13 for token verification.

[`sample-app/.env.example`](../sample-app/.env.example) likewise omits it — this
was an intentional gap in the sample to demonstrate Orient's value.

**Add to README Configuration section:**
> `JWT_SECRET` – secret used to sign and verify session tokens. **Required.**

## Finding 7 — `SESSION_TTL_MINUTES` and `LOG_LEVEL` not documented

**README claim:** No mention of these variables.

**Reality:**  
[`src/config.js`](../sample-app/src/config.js:28-31) lines 28–31:
```js
sessionTtlMinutes: parseInt(process.env.SESSION_TTL_MINUTES, 10) || 60,
logLevel: process.env.LOG_LEVEL || 'info',
```
Both are optional with safe defaults (`60` minutes and `'info'` respectively), so
the app does not crash without them. However, a developer who needs to adjust
session lifetime or logging verbosity has no way to discover these knobs from
the README.

[`src/middleware/logger.js`](../sample-app/src/middleware/logger.js:6) uses
`LOG_LEVEL` with accepted values `debug | info | warn | error`.

**Add to README Configuration section:**
> `SESSION_TTL_MINUTES` – session lifetime in minutes (default: `60`).  
> `LOG_LEVEL` – logging verbosity: `debug | info | warn | error` (default: `info`).
